# 7 行提示词，让 DeepSeek-V4-Flash 追平 V4-Pro

> 从 20 条追问到 7 行自我诊断——一次代码审查实验的完整复盘

---

## 动机

我在用 DeepSeek-V4-Flash 做方案审查时发现，同样的任务，Flash 经常遗漏 Pro 能发现的问题。直觉上这不是推理能力的差距——两者在裸奔测试中差距不大。我怀疑是 Flash 的**思维习惯**有问题，不是脑子不够用。于是设计了一组实验验证这个猜想。

---

## 实验结构

实验分两条线并行：

**调度中心流派：** 不断给 Flash 加能力——审视框架、因果链、元认知、四象限。目标是追平 Pro+Pro 基线（85% 发现率）。15+ 轮迭代，提示词膨胀到 ~3000 字。

**基础思维链流派：** 不给解法，只诊断 Flash 的思维问题。1 轮迭代，7 行提示词。

---

## 调度中心流派的完整升级经过

### 基线：Pro+Pro

金标准文档（20 个故意埋入的已知缺陷）：**265s，85% 发现率（17/20），4 条因果链。**

### v1-v4：审视框架蒸馏

从 Pro 独有发现反推出 20 条追问——凡是锁检查互斥、凡是临时资源检查清理、凡是 I/O 检查同步异步。发现率 55%→90%。但这是从金标准缺陷反向枚举的，换项目就失效。

### v5-v9：调度中心 + 并发 + 自适应

Flash 调度中心派发 N 个分身并发审查，加因果链教学、元认知评估、四象限注意力分配。金标准追平基线（85%），实战项目也有效。但架构臃肿。

### v10：泛化追问 + 文档声明检查 + 存疑搜索 + 隐式边界

关键转折——不再加审视框架条目，改为在调度中心核验阶段做三件事：

| 新增机制 | 版本 | 消灭的问题类型 |
|------|------|------|
| 文档声明完整性检查 | v10.2 | "文档写了但代码没实现"类假阳性（A2/A5/A7） |
| 🔍 存疑搜索验证 | v10.4 | "分身不知道所以漏了"类缺口（③跨分区/④glob替代） |
| 隐式边界触发词 | v10.5 | "文档没写清楚的声明"类缺口（A3分批） |

### v10.5 最终成绩

| 指标 | Pro+Pro 基线 | v10.5 | 差距 |
|------|------|------|------|
| 发现率 | 85%（17/20） | **~95-100%（19-20/20）** | +10-15pp |
| 耗时 | 265s | 340s | +28% |
| 模型成本 | Pro × N | **Flash × N** | 1/3 |

## 基础思维链流派

### 动机

调度中心流派的提示词膨胀到几十条规则后，我让 LLM 停手。问题不是 Flash 不会审查——是它总想一口气扫完所有维度，每个都扫不深。Pro 之所以稳定，是因为它会自然地分段。

### 方案

不给解法，只写诊断。LLM 写了 7 行：

```
1. 总想一口气回答所有问题/处理所有事情，不会分批/分块/分部分/分步骤处理，
   导致思考深度被占满丢失大量细节。
2. 阅读代码/思考方案，方式也不会拆分，总想一把梭，跟问题1本质同源。
```

| | 基础思维链 | 调度中心 v8 |
|------|------|------|
| 耗时 | **48s** | 292s |
| 发现数 | 23 | **34** |

### 交叉验证

基础思维链在调度中心的主场（金标准）上，48 秒发现了之前十几轮都没发现的跨分区问题。调度中心在自己的主场上展现了系统性的因果链分析能力。

**各自主场守住了，对方主场也没输。**

---

## 结论

**蒸馏不是"把大模型的答案翻译成小模型的指令"，是"让小模型知道自己容易犯什么错"。**

调度中心流派用 15 轮迭代证明了可以系统性超越 Pro。基础思维链流派用 7 行证明了最简方案就能追平——关键是让 Flash 知道自己的弱点，而不是替它想好一切。

两条线走到最后指向同一个认知：**提示词优化的天花板不是"加多少条规则"，是"模型有没有意识到自己该怎么工作"。**
